在家庭 **Homelab** 或软路由网络架构中，许多高级玩家都会选择将 **AdGuard Home** 与 **Sing-box** 组合使用，以打造极致的内网体验：

- **AdGuard Home**：负责前台拦截。它拥有极其精美的 Web UI 控制台、直观的查询日志监控、以及百万级的广告与隐私域名拦截规则（Adblock List）。
- **Sing-box**：负责后台分流。凭借其高性能的内建 DNS 解析引擎与规则路由分流（Rule Set），能实现最精确的节点调度和分流。

然而，**“双主解析”面临的最大敌人是 DNS 环流（DNS Loop，死循环）**：
`客户端请求 -> AdGuard Home -> Sing-box -> 路由分流走 direct -> 调用系统/软路由默认 DNS（即 AdGuard Home） -> 回到 AdGuard Home ...`

这个死循环会在顷刻间让你的 CPU 占用率飙升到 100%，内存爆满，导致家庭内网全面瘫痪。

今天，我们将通过严密的端口规划与分流配置，教你如何让 AdGuard Home 与 Sing-box 完美防环流配合，实现极致延迟的纯净网络。

---

## 📐 一、极致 DNS 接力架构拓扑设计

为了彻底避免 DNS 环流，我们必须建立**单一方向的接力链条**：

```
[局域网终端设备]
       │
       ▼ (DNS 请求，UDP 53 端口)
┌─────────────────────────────────┐
│     AdGuard Home (前台)         │ ───► 负责：网页广告拦截、日志监控、缓存
└─────────────────────────────────┘
       │
       ▼ (过滤后的合法请求转发，UDP 5353 端口)
┌─────────────────────────────────┐
│     Sing-box DNS (后台)         │ ───► 负责：分流判断 (国内直连 vs 国外代理)
└─────────────────────────────────┘
       │
       ├─► (国内域名) ──► 物理直连 ──► 公共直连 DNS (如 223.5.5.5) *绕过本地网卡*
       │
       └─► (国外域名) ──► 代理出站 ──► 加密代理 DNS (如 1.1.1.1)
```

### 💡 避坑关键点：

为了切断循环，**Sing-box 在解析国内直连域名时，其出站 DNS 请求必须直接发往公网公共 DNS（如阿里或腾讯 DNS），绝对不能指向本地的 AdGuard Home。**

## 🛠️ 二、第一步：配置 Sing-box (后台监听 5353)

我们首先配置 Sing-box 的内建 DNS 模块，使其作为 AdGuard Home 的上游解析服务器。

编辑 Sing-box 的配置文件 `config.json`：

```json
{
  "inbounds": [
    // 监听本地 5353 端口，接收来自 AdGuard Home 的 DNS 请求
    {
      "type": "direct",
      "tag": "dns-in",
      "listen": "127.0.0.1",
      "listen_port": 5353
    }
  ],
  "outbounds": [
    { "type": "direct", "tag": "direct" },
    {
      "type": "socks",
      "tag": "proxy",
      "server": "127.0.0.1",
      "server_port": 1080
    }
  ],
  "dns": {
    "servers": [
      // 1. 国内直连解析：配置 detour 强制其物理网卡直连，绝不能指回本地！
      {
        "tag": "dns-direct",
        "address": "223.5.5.5",
        "detour": "direct"
      },
      // 2. 国外代理解析：通过代理出站进行防污染查询
      {
        "tag": "dns-proxy",
        "address": "https://1.1.1.1/dns-query",
        "detour": "proxy"
      }
    ],
    "rules": [
      // 路由分流规则：如果是国内网站，使用国内直连 DNS 解析
      {
        "rule_set": ["geosite-cn"],
        "server": "dns-direct"
      },
      // 其余默认走代理加密 DNS 解析
      {
        "outbound": "any",
        "server": "dns-proxy"
      }
    ]
  },
  "rule_set": [
    {
      "tag": "geosite-cn",
      "type": "remote",
      "format": "binary",
      "url": "https://raw.githubusercontent.com/lyc8503/sing-box-rules/rule-set-geosite/geosite-cn.srs",
      "download_detour": "proxy"
    }
  ]
}
```

## 🛠️ 三、第二步：配置 AdGuard Home (前台监听 53)

完成 Sing-box 的配置后，我们进入 AdGuard Home 的 Web 管理后台（假定为 `http://192.168.1.2:3000`）。

### 1. 设置上游 DNS (Upstream DNS)

进入 **“设置”** -> **“DNS 设置”**：
在 **“上游 DNS 服务器”** 框中，清空所有默认地址，**仅输入 Sing-box 的监听地址**：

```
127.0.0.1:5353
```

### 2. 设置 Bootstrap DNS 服务器

Bootstrap DNS 用于解析上游 DoH/DoT 服务的域名。因为我们的上游直接是本地 IP 端口 `127.0.0.1:5353`，为了避免 Bootstrap 自身查询引发环流，我们在 **“Bootstrap DNS 服务器”** 框中直接填写公网直连 IP：

```
223.5.5.5
119.29.29.29
```

### 3. 选择解析模式

在下方的“测试上游 DNS”无误后，将“选择模式”修改为 **“并行查询”** 或 **“最快 IP 地址”**，点击保存。

---

## 🔒 四、第三步：优化缓存策略与降延迟

AdGuard Home 与 Sing-box 都有各自的 DNS 缓存模块。如果两者同时开启大容量缓存，不仅会消耗多余的内存，还可能因为缓存过期时间（TTL）冲突导致你修改的 Hosts 记录迟迟不生效。

### 💡 最佳优化推荐：

- **AdGuard Home（关闭或极小缓存）**：在 AdGuard Home 的“DNS 设置”里，将 **“缓存大小”** 限制在很小的值（例如 `1024` 字节），或者设为 `0` 禁用。因为我们主要需要它的规则过滤功能，而解析结果缓存我们让更贴近网络底层的 Sing-box 去做。
- **Sing-box（开启高效缓存）**：让 Sing-box 模块去常驻缓存，这样国内和国外的分流结果解析能够以毫秒级响应，避免重复建连。
