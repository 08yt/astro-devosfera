## 三、生产级统一部署蓝图 (`compose.yml`)

我们使用一个顶级的统一 Docker Compose 文件，通过自定义 Bridge 网络将组件打通，同时对外部暴露做严格隔离：

```yaml
# /opt/ai-factory/compose.yml
services:
  # 1. 向量数据库 (存储企业与个人知识库)
  qdrant:
    image: qdrant/qdrant:latest
    container_name: factory-qdrant
    restart: unless-stopped
    volumes:
      - ./data/qdrant:/qdrant/storage
    networks:
      - ai-internal-net

  # 2. n8n 数据库存储
  n8n-postgres:
    image: postgres:16-alpine
    container_name: factory-n8n-db
    restart: unless-stopped
    environment:
      POSTGRES_USER: n8n_admin
      POSTGRES_PASSWORD: "YOUR_SECURE_PG_PASSWORD"
      POSTGRES_DB: n8n_db
    volumes:
      - ./data/postgres:/var/lib/postgresql/data
    networks:
      - ai-internal-net

  # 3. 业务调度中枢 n8n
  n8n:
    image: docker.n8n.io/n8nio/n8n:latest
    container_name: factory-n8n-app
    restart: unless-stopped
    ports:
      - "127.0.0.1:5678:5678" # 仅本地回环，走反代
    environment:
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=n8n-postgres
      - DB_POSTGRESDB_PORT=5432
      - DB_POSTGRESDB_DATABASE=n8n_db
      - DB_POSTGRESDB_USER=n8n_admin
      - DB_POSTGRESDB_PASSWORD="YOUR_SECURE_PG_PASSWORD"
      - N8N_HOST=n8n.yourlan.local
      - N8N_PROTOCOL=https
      - N8N_ENCRYPTION_KEY="YOUR_SUPER_LONG_RANDOM_KEY_AT_LEAST_32_CHARS"
      - EXECUTIONS_DATA_MAX_AGE=168
    volumes:
      - ./data/n8n:/home/node/.n8n
    depends_on:
      - n8n-postgres
    extra_hosts:
      - "host.docker.internal:host-gateway"
    networks:
      - ai-internal-net

  # 4. 安全 Docker Socket 代理 (阻断写操作，保护宿主机)
  docker-proxy:
    image: tecnativa/docker-socket-proxy:latest
    container_name: factory-docker-proxy
    restart: unless-stopped
    environment:
      - CONTAINERS=1
      - INFO=1
      - POST=0
      - DELETE=0
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
    networks:
      - ai-internal-net

networks:
  ai-internal-net:
    name: ai-internal-net
    driver: bridge
```

_(注：Ollama 建议根据上一篇指南原生安装在宿主机或带有显卡驱动的专用容器中，通过 `http://host.docker.internal:11434` 供全网容器共享使用)_。

## ❓ 常见问题与 AI 快问快答 (FAQ)

**Q：整个四件套全部跑起来，冷机待机占用多少内存？**

A：在不加载大模型（模型未推理）的状态下，PostgreSQL + Qdrant + n8n + Dify 基础后台组件合计占用内存仅约 **1.5GB – 2.2GB**，非常轻量。显存与高内存占用仅在 Ollama 推理或模型常驻时发生（可通过 `OLLAMA_KEEP_ALIVE=5m` 设置空闲 5 分钟自动释放显存）。

**Q：为什么不把所有东西塞进一个超大的 All-in-One 镜像里？**

A：微服务架构的核心价值在于**解耦与容错**。如果写在一个大容器里，某个组件崩溃（例如 Ollama 显存溢出）会导致调度器和数据库跟着挂掉。通过 Docker Compose 分离服务，n8n 或数据库可以数月不重启，单独升级 Ollama 也不影响已有数据的完整性。

**Q：这套架构后续如何备份与跨机器迁移？**

A：得益于清晰的目录映射：只要备份 `./data/` 目录以及对应数据库的 `.dump` 导出文件，到任何一台新的 Linux 机器上，执行 `docker compose up -d`，整座 AI 工厂即可在几分钟内完好无损地原地复活！
