在家庭 **Homelab** 或企业软路由网络架构中，追求极致稳定的玩家往往会采取两项双重保障策略：

1.  **物理物理双宽带**：拉两条不同运营商的宽带（例如电信 CN2 + 移动大宽带），通过 OpenWrt 的 **MWAN3** 模块进行叠加或备份。
2.  **多节点冗余分流**：在 **Sing-box** 客户端中配置多个来自不同地区（如香港 IPLC、美西 GIA、日本软银）的代理出站节点。

然而，如果配置不当，当其中某一条物理宽带掉线、或者某个 VPS 节点突然遭遇 IP 阻断时，家庭内网常常会出现**长达数分钟的卡顿死锁**，极大地影响上网体验。

今天，我们将手把手教你如何利用 Sing-box 的 **多出站（Multi-Outbound）** 策略组，配合 OpenWrt 实现物理宽带叠加与节点秒级无感故障转移！

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **原理解析**：结合 Sing-box 的 `urltest` 自动测速策略组与 OpenWrt MWAN3 模块，实现“物理多宽带（电信+移动）+ 节点链路”的双重多路故障冗余。
> - **参数微调**：`tolerance: 50` 能够防止节点因 1-2ms 的微小延迟抖动而频繁跳切导致长连接中断；`interval: "3m"` 保证低开销后台健康检查。
> - **最佳拓扑**：建议采用“IPLC/IEPL 专线为主节点，海外 CN2 GIA VPS 为容灾备用节点”的双组架构。

## 📐 一、多出站策略组核心模型：urltest vs selector

在 Sing-box 配置文件中，处理多个节点出站主要依赖以下两种组（Outbound Group）类型：

- **`selector`（手动选择组）**：在 UI 界面上手动勾选某一个指定节点。适合对特定 IP 有固定需求（如解锁 Netflix 或 ChatGPT 所在节点）的场景。
- **`urltest`（自动测速选优组）**：🏆 **秒级容灾核心**。 Sing-box 会按照设定的时间间隔（如每 3 分钟）向指定的健康检查地址（如 `gstatic.com/generate_204`）发送 HTTP 测试。系统会自动将流量切向当前延迟最低、且无丢包的节点上。

---

## 🛠️ 二、第一步：配置 Sing-box 自动故障转移 JSON

在 Sing-box 的配置文件 `config.json` 的 `outbounds` 数组中，我们定义各个独立节点，并使用 `urltest` 策略组将它们包容进来：

```json
{
  "outbounds": [
    // 1. 自动测速与故障转移主策略组
    {
      "type": "urltest",
      "tag": "proxy-auto-group",
      "outbounds": [
        "node-dmit-hk-iplc",
        "node-bwh-us-gia",
        "node-cloudcone-us"
      ],
      "url": "https://www.gstatic.com/generate_204",
      "interval": "3m", // 每 3 分钟自动后台健康检查一次
      "tolerance": 50, // 容差区间（毫秒）：只有当新节点延迟比旧节点低 50ms 以上时才切换，避免频繁震荡
      "idle_timeout": "30m" // 空闲超时
    },

    // 2. 独立出站节点 A：香港 IPLC
    {
      "type": "vless",
      "tag": "node-dmit-hk-iplc",
      "server": "1.2.3.4",
      "server_port": 443,
      "uuid": "your-uuid",
      "flow": "xtls-r-flow"
      // tls/reality 参数...
    },

    // 3. 独立出站节点 B：美西 CN2 GIA
    {
      "type": "hysteria2",
      "tag": "node-bwh-us-gia",
      "server": "5.6.7.8",
      "server_port": 443,
      "auth": "your-password"
      // hop_ports 参数...
    },

    // 4. 物理直连出站
    {
      "type": "direct",
      "tag": "direct"
    }
  ]
}
```

### 💡 `tolerance` 容差参数精妙之处：

如果将 `tolerance` 设为 `0`，只要节点 A 延迟比节点 B 稍微快了 1ms，系统就会瞬间切换过去。在网络抖动时，这会导致建立好的 TCP 长连接（如游戏或直播）频繁断开。**设置为 50ms 到 100ms** 能在保障流畅性的前提下，实现最优雅的稳健切替。

## 🌐 三、第二步：配合 OpenWrt MWAN3 实现物理双宽带叠加

如果你的软路由接入了两条物理宽带（如 WAN1 为电信，WAN2 为移动）：

### 1. 配置 MWAN3 负载均衡规则

在 OpenWrt 管理后台：进入 **网络** -> **MWAN3 多 WAN 负载均衡**。

- 设置接口监控地址（如 `223.5.5.5`）。
- 在 **“成员 (Members)”** 中设置权重：例如电信权重设为 `3`，移动权重设为 `2`。
- 在 **“策略 (Policies)”** 中创建一个名为 `balanced_all` 的负载均衡策略，包含这两条成员。

### 2. Sing-box 多出站绑定

通过这种结合，即使你的物理宽带 WAN1 意外断网，OpenWrt MWAN3 会在 3 秒内将物理流量切到 WAN2 宽带上；随后 Sing-box 发现旧链路响应超时，会通过 `urltest` 自动将节点选优切向在 WAN2 上表现最佳的代理节点，实现**双重保险下的零感秒切**。

## ❓ 常见问题与 AI 快问快答 (FAQ)

### Q1: `urltest` 的健康检查测试地址（`url`）该如何挑选？

**答**：建议使用 `https://www.gstatic.com/generate_204` 或 `http://cp.cloudflare.com/generate_204`。这类 204 响应接口返回数据量极小（0 字节 Body），既能准确测试延迟与连通性，又不会白白浪费测试流量。

### Q2: 为什么开启多出站节点自动切换后，部分网页登录状态频繁掉线？

**答**：某些对安全敏感的网站（如银行、Paypal 或特定论坛）会校验用户的出口 IP 地址。如果 `urltest` 策略组的 `tolerance` 设得太小引发频繁换节点 IP，就会被网站判为异常登出。建议将敏感域名专门划分给固定节点（`selector`）或者放行直连。
