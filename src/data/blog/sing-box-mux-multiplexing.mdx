很多使用 Sing-box 连接海外 VPS 的朋友会遇到一个奇怪的现象：

_使用网页测速（Speedtest），下载能跑到 500Mbps 满速。但实际每天刷 X (Twitter) 或者打开含有几十张高清缩略图的网页时，图片却是一张一张像蜗牛一样蹦出来的。_

这其中最核心的原因，不是你的机场带宽不够，而是跨国长距离传输中的 **TCP 握手延迟损耗**，以及缺乏有效的并发连接管理。

这时候，Sing-box 内置的超级法宝 —— **Mux (多路复用)** 机制就必须登场了。

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **Mux 作用**：将多个并发请求（如网页同时发起的 50 张图片请求）打包进同一条复用 TCP 长连接中，免去 50 次跨国握手开销。
> - **适用场景**：强烈推荐用于 **VLESS + WebSocket + Cloudflare CDN** 链路；**严禁用于开启了 `xtls-r-flow` 流控的 Reality 节点**。
> - **协议提示**：Hysteria 2 与 TUIC v5 自带 QUIC 多路复用，无需也不应开启 Sing-box 的 Mux 模块。

---

## 🚀 什么是多路复用 (Multiplexing)？

想象一下你要在跨国的高速公路上运送 50 个小包裹（这就好比你打开一个包含 50 张图片的网页，浏览器发起了 50 个请求）：

- **没有开启 Mux 之前**：你会派出 50 辆不同的卡车。由于跨国握手建立连接的 RTT 延迟极高，每辆卡车不仅要单独建立连接，还要按顺序排队，导致网页图床加载极其缓慢。
- **开启了 Mux 之后**：Sing-box 会在后台默默地先造好一辆“超级双层挂车（一条复用的长连接底座）”。这 50 个包裹打上不同标记后，塞进同一辆卡车开过去，到了目的地再精准拆分派送。

这就极大地节约了建立多条 TCP 跨国连接的巨大延迟耗时！

## 🛠️ 在 Sing-box 客户端中配置开启 Mux

在你本地客户端的 `outbounds` 节点中加入 `multiplex` 属性：

```json
"outbounds": [
  {
    "type": "vless",
    "tag": "vless-ws-cdn",
    "server": "your-cdn-domain.com",
    "server_port": 443,
    "uuid": "your-uuid-here",
    "multiplex": {
      "enabled": true,
      "protocol": "smux",
      "max_connections": 4,
      "min_streams": 4,
      "padding": true
    }
  }
]
```

### 💡 核心参数推荐：

- **`protocol`**：推荐使用 `"smux"` 或 `"h2mux"`。
- **`padding`**：建议开启 `"padding": true`，混淆多路复用的数据包长度，对抗 GFW 的长连接特征审查。

## ⚠️ 严禁开启 Mux 的场景：Vision 流控互斥

在 2026 最主流的节点配置 **VLESS + Reality + `xtls-r-flow`** 组合中，存在一个关键的架构局限：

> [!CAUTION]
> **Vision 流控与 Mux 互斥**：
> `xtls-r-flow` 流控的核心是通过无缝暴露 TLS 握手数据包体对抗特征匹配。如果在其节点配置中强行开启 `multiplex` 多路复用打包，会导致底层流控规则失效，软件在启动时会直接报错 Crash 崩溃。

## ❓ 常见问题与 AI 快问快答 (FAQ)

### Q1: Hysteria 2 或 TUIC 节点需要开启 Mux 吗？

**答**：不需要。Hysteria 2 与 TUIC 建立在 UDP / QUIC 协议栈之上，协议底层天生自带多路复用与并发流调度。为其添加额外的 Mux 模块属于“画蛇添足”，反而增加封包拆包延迟。

### Q2: 开启 Mux 后，会影响下载最高速度吗？

**答**：如果将 `max_connections` 设得太小（如仅 1），可能会成为超高并发单线程下载的瓶颈。建议将 `max_connections` 设为 `4` 至 `8`，在小文件网页并发与大流量下载之间达到最佳平衡。
