很多刚入坑 **HomeLab**（家庭实验室）的朋友，在内网跑起了 PVE、Docker 服务（博客、NAS、Alist 网盘），但一出门想要用手机在外网访问时瞬间傻眼 —— 运营商死活不给公网 IPv4！

过去搭建 **FRP** 依赖有公网 IP 的便宜 VPS，不仅配置繁琐，且带宽受限于中转 VPS 的小水管。

今天我们要介绍现代内网穿透的王牌工具 ── **Cloudflare Tunnel (旧称 Argo Tunnel)**。

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **底层原理**：本地 `cloudflared` 守护进程主动向 Cloudflare 全球边缘集群建立加密长连接；外部访问域名时，CF 将流量经由该隧道安全转发给内网服务 —— 全程无需公网 IP、无需路由器端口映射。
> - **零端口暴露**：路由器和光猫无需开启任何端口转发（Port Forwarding），天然免疫全网端口扫描与 DDoS 攻击。
> - **全自动 HTTPS**：由 Cloudflare 边缘端直接提供 SSL 证书，全链路强制 HTTPS 加密。
> - **Zero Trust 加固**：配合 Cloudflare Access，可为任意内网后台强制添加邮箱 OTP 验证码防护。

## 🛠️ 一、部署 `cloudflared`：两种方式二选一

先在 [Cloudflare One 控制台](https://one.dash.cloudflare.com/) 的 **Networks -> Tunnels** 创建隧道并复制 Token。

### 方式 A：Docker 一行命令（最快）

```bash
docker run -d \
  --name cloudflared \
  --restart always \
  cloudflare/cloudflared:latest \
  tunnel --no-autoupdate run --token YOUR_CLOUDFLARE_TUNNEL_TOKEN
```

### 方式 B：Docker Compose（推荐长期运行）

在内网主机（NAS / 软路由 / Linux）创建 `compose.yaml`：

```yaml
services:
  cloudflared:
    image: cloudflare/cloudflared:latest
    container_name: cloudflared_tunnel
    restart: unless-stopped
    command: tunnel --no-autoupdate run --token YOUR_CLOUDFLARE_TUNNEL_TOKEN
```

启动：`docker compose up -d`。

## 🌐 二、配置 Public Hostname 域名映射

1. 回到 Cloudflare One 控制台，进入 **Networks -> Tunnels**，点击刚连上线的隧道；
2. 进入 **Public Hostname**（或 Configure -> Public Hostname），添加路由：
   - **Subdomain**：`nas`（即 `nas.yourdomain.com`）
   - **Domain**：选择你在 CF 托管的域名
   - **Type**：`HTTP`
   - **URL**：内网服务的真实地址，如 `http://192.168.1.100:5000`
3. 保存后，外网直接访问 `https://nas.yourdomain.com` 即可秒级穿透直达！

## 🔐 三、进阶加固：Cloudflare Access 零信任门禁

内网后台（PVE、NAS 管理页）一旦暴露在公网域名下，建议再加一道门：

在 Zero Trust 控制台为该域名创建 **Access Policy**，要求访问者先通过邮箱 OTP 验证。配置细节见 [《使用 Cloudflare Access 配置零信任内网穿透与 SSO 验证》](/posts/cloudflare-zero-trust-access-guide/)。

## ❓ 常见问题与 AI 快问快答 (FAQ)

### Q1: 大陆网络访问 Cloudflare Tunnel 绑定的域名会慢吗？

**答**：Cloudflare 节点在中国大陆走普通骨干网出境，晚高峰可能有一定延迟。若追求极致低延迟，可用海外 **DMIT** 或 **搬瓦工** 等拥有 **中国电信 CN2 GIA** / **联通 AS9929** 回程线路的 VPS 自建 FRP 隧道作为补充。

### Q2: 用 Tunnel 传输大文件或跑 Jellyfin 视频流会被封号吗？

**答**：Cloudflare ToS 对纯非 HTML 大流量（如 TB 级影视串流）有限制。建议：Web 管理面板、Git、密码库走 Tunnel；Jellyfin/Emby 等媒体流改用公网 IPv6 + DDNS 直连（见 [《全面拥抱公网 IPv6 + DDNS》](/posts/why-embrace-ipv6-ddns/)）。

### Q3: 和传统 FRP 相比，Tunnel 的最大优势是什么？

**答**：三点：① 不需要一台有公网 IP 的中转 VPS；② 零端口暴露，安全模型完全不同；③ HTTPS 证书与 DDoS 防护全由 Cloudflare 边缘承担，免运维。
