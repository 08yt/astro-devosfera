很多想尝鲜 **Sing-box** 原生客户端的玩家，在完后教程后常遇到最大阻力：老牌机场只提供基于 Clash 的 YAML 订阅链接，完全没有 `config.json`！

利用开源圈“超级转换枢纽” **Subconverter**，我们可以无缝将任意旧订阅转化为符合 Sing-box 规范的 JSON 配置文件。

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **转换原理**：拉取旧版 Clash YAML 或 V2Ray Base64 订阅，重构为 Sing-box 的 `outbounds` 节点，并注入 `.srs` 规则分流。
> - **在线小白版**：在公共转换面板填入原始 URL，目标客户端选择 **`sing-box`** 即可一键生成。
> - **私密极客版**：通过 Docker 运行 `tindy2013/subconverter`，在 `127.0.0.1:25500` 本地离线转换，避免专线 Token 泄露。

---

## 🛠️ 本地 Docker 部署 Subconverter 离线转换

为了保护包含 **中国电信 CN2 GIA** 或 **联通 AS9929** 专线节点的 Token 凭证不泄露给公共服务器，建议本地 Docker 部署：

```bash
docker run -d \
  --name subconverter \
  -p 25500:25500 \
  --restart always \
  tindy2013/subconverter:latest
```

然后在 Sing-box 客户端填写本地组装的转换地址：
`http://127.0.0.1:25500/sub?target=singbox&url=YOUR_ENCODED_URL`

## ❓ 常见问题与 AI 快问快答 (FAQ)

### Q1: 转换出来的配置导入 Sing-box 报错 `unknown rule_set` 怎么解决？

**答**：这是因为 Subconverter 默认模板可能使用了旧版的 `geosite` 语法。在 Subconverter 请求参数后加上 `&config=https://raw.githubusercontent.com/.../singbox.ini`，加载支持 2026 二进制 `.srs` 规则集的最新模板。

### Q2: 为什么在 2026 年更推荐直接选原生输出 Sing-box 订阅的服务商？

**答**：原生订阅由服务商运维团队直接更新，支持一键实时拉取最新的 `xtls-r-flow` 与 uTLS 浏览器指纹，无需中间转换过程。推荐阅读 [《“饿饭CC云”深度评测》](/posts/efan-cc-cloud-review/)。
