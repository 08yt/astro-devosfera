很多开发者在配置 Nginx 反向代理时，面对 `location` 语法常常靠“玄学试错”：
有的是 `location = /`，有的是 `location ^~ /api/`，还有 `location ~* \.php$`。

当遇到前后端分离、静态资源缓存与 API 接口转发混搭时，抄来的规则经常互相截胡导致 404 或代理穿透。

Nginx 的 Location 路由有一套严密且精确的**优先级判定算法**。掌握了这套逻辑，复杂的网关路由将一目了然！

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **终极优先级阶梯**：
>   1. **`=` 精确匹配**：完全相等立即终止搜寻（最高优先级）。
>   2. **`^~` 非正则前缀匹配**：最长前缀匹配且阻断后续所有正则表达式。
>   3. **`~` / `~*` 正则匹配**：按配置文件**从上到下的顺序**匹配，首个命中即生效。
>   4. **普通前缀匹配（如 `/api`）**：按最长匹配暂存，只有所有正则都不匹配时才兜底生效。
>   5. **`/` 通用匹配**：最低优先级保底。

## 📊 Location 匹配修饰符对照表

| 符号修饰符   | 匹配类型                            | 优先级与行为                             | 典型示例                            |
| :----------- | :---------------------------------- | :--------------------------------------- | :---------------------------------- |
| **`=`**      | 精确匹配 (Exact)                    | 🏆 **最高优先级**，命中后立即退出匹配    | `location = /login { ... }`         |
| **`^~`**     | 优先前缀匹配 (Preferential)         | 命中后**忽略所有后续正则**，直接生效     | `location ^~ /static/ { ... }`      |
| **`~`**      | 区分大小写正则 (Case-sensitive)     | 按在配置文件中**从上到下**的顺序匹配     | `location ~ \.(png\|jpg)$ { ... }`  |
| **`~*`**     | 不区分大小写正则 (Case-insensitive) | 同上，忽略大小写                         | `location ~* \.(gif\|mp4)$ { ... }` |
| **无修饰符** | 普通前缀匹配 (Prefix)               | 找出最长匹配作为候补，待正则未命中时兜底 | `location /api/ { ... }`            |
| **`/`**      | 通用兜底匹配 (Catch-all)            | 最低优先级                               | `location / { ... }`                |

## ⚠️ 生产环境头号避坑：`proxy_pass` 的尾部斜杠 `/`

在 `location` 中配置反向代理时，`proxy_pass` 末尾有没有斜杠代表截然不同的转发行为：

### 1. 目标地址带斜杠（URI 替换）

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080/; # 注意末尾有 /
}
```

> **转发结果**：访问 `/api/v1/user` 会被替换转发为 `http://127.0.0.1:8080/v1/user`（去掉了 `/api/`）。

### 2. 目标地址不带斜杠（完整路径追加）

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8080; # 注意末尾没有 /
}
```

> **转发结果**：访问 `/api/v1/user` 会原封不动转发为 `http://127.0.0.1:8080/api/v1/user`。
