在互联网世界里，**DNS（域名系统）** 常常被称为“网络路标”。然而，绝大多数用户日常使用的默认 DNS（如运营商分发地址或公共 `114.114.114.114`），普遍面临两大严重隐患：

1.  **隐私泄露**：传统的 DNS 查询完全以明文 UDP 报文形式发送，中间链路上的网络运营商（ISP）和监听设备可以轻易窥探你访问的所有网站域名。
2.  **DNS 污染与劫持**：在跨境网络或特定内网下，DNS 请求极易被篡改污染，导致无法访问或跳转到虚假广告页面。

为了解决这个问题，**DoH（DNS over HTTPS）** 与 **DoT（DNS over TLS）** 加密技术应运而生。它们将 DNS 请求打包在 HTTPS 或 TLS 加密协议中，从根本上杜绝了中间人监听与篡改。

许多极客尝试自建 _AdGuard Home_ 或 _Pi-hole_，但由于其常驻内存大且过滤规则匹配效率较低，容易遭遇 OOM 崩溃。今天，我们将利用极其轻量、匹配效率惊人的 **Sing-box** 作为 DNS 服务端，在 VPS 上搭建一台私有加密的 DoH/DoT 服务器，实现安全、无污染且过滤广告的极致解析体验！

## 🧐 一、加密 DNS 的选择：DoH 还是 DoT？

- **DoT (DNS over TLS)**：运行在特定的 `853` 端口，采用纯 TLS 通道传输。由于端口固定，它的**连接握手开销相对较低，解析更迅速**，适合移动端（如 Android 系统级私有 DNS）和路由器使用。
- **DoH (DNS over HTTPS)**：运行在标准的 `443` 端口（混淆在标准的 HTTPS 流量中），具有**极强的穿透力**，几乎在任何防火墙严格控制的网络环境下都无法被识别阻断。

今天，我们将介绍如何在一台 Linux 服务器上部署 Sing-box，并同时开启这两种解析服务。

## 🛠️ 二、服务端部署实操

本教程以运行 Debian/Ubuntu 系统的海外 VPS 为例。

### 1. 准备 SSL 证书

因为是加密 DNS，你的 DoH/DoT 服务器必须有可信的 SSL 证书。建议使用 `acme.sh` 或 `Certbot` 为你的域名申请一张免费的 Let's Encrypt 证书：

申请成功后，假设证书文件存放在：

- 证书链：`/etc/ssl/dns.crt`
- 私钥：`/etc/ssl/dns.key`

### 2. 编写 Sing-box 服务端 `config.json`

我们在 `/etc/sing-box/` 目录下创建配置文件：

```json
{
  "log": {
    "level": "info",
    "timestamp": true
  },
  "inbounds": [
    // 1. DoT 监听模块 (Port 853)
    {
      "type": "direct",
      "tag": "dot-in",
      "listen": "::",
      "listen_port": 853,
      "tls": {
        "enabled": true,
        "server_name": "dns.yourdomain.com",
        "certificate_path": "/etc/ssl/dns.crt",
        "key_path": "/etc/ssl/dns.key"
      }
    },
    // 2. DoH 监听模块 (Port 443)
    {
      "type": "direct",
      "tag": "doh-in",
      "listen": "::",
      "listen_port": 443,
      "tls": {
        "enabled": true,
        "server_name": "dns.yourdomain.com",
        "certificate_path": "/etc/ssl/dns.crt",
        "key_path": "/etc/ssl/dns.key"
      }
    }
  ],
  "outbounds": [
    {
      "type": "direct",
      "tag": "direct-out"
    }
  ],
  "dns": {
    "servers": [
      // 上游安全递归 DNS：使用 Cloudflare 和 Google 的加密 DoH 节点
      {
        "tag": "cloudflare-dns",
        "address": "https://1.1.1.1/dns-query",
        "detour": "direct-out"
      },
      {
        "tag": "google-dns",
        "address": "https://8.8.8.8/dns-query",
        "detour": "direct-out"
      }
    ],
    "rules": [
      // 过滤广告域名：如果解析请求命中 geosite-ads，强行拦截返回空地址
      {
        "rule_set": ["geosite-ads"],
        "server": "block"
      }
    ]
  },
  // 规则集声明（编译后的二进制 .srs 格式以实现极速匹配）
  "rule_set": [
    {
      "tag": "geosite-ads",
      "type": "remote",
      "format": "binary",
      "url": "https://raw.githubusercontent.com/lyc8503/sing-box-rules/rule-set-geosite/geosite-category-ads-all.srs",
      "download_detour": "direct-out",
      "update_interval": "1d"
    }
  ]
}
```

### 3. 启动 Sing-box 服务

运行并设置开机自启：

```bash
systemctl daemon-reload
systemctl enable sing-box --now
systemctl status sing-box
```

## 🔒 三、防御公网 DNS 放大攻击与加固

自建 DNS 暴露在公网上时，极易被扫描器扫出来。黑客会向你的服务器发送海量的欺骗性伪造 IP 查询，把你的 DNS 服务器当作放大器去攻击其他网站（即 **DNS 放大攻击/DDoS**）。

### 1. 严格使用加密端口

在我们的配置中，我们**只开启了 443 (DoH) 和 853 (DoT) 加密端口，彻底关闭了 53 UDP/TCP 明文端口**。这能直接过滤掉 99% 的自动化扫描攻击，因为绝大多数扫描器仅扫描标准的 53 端口。

### 2. 部署防火墙限流 (iptables/ufw)

为了防止同一个 IP 频繁建立 TLS 握手，可以使用 `ufw` 实施请求速率限制：

```bash
# 限制 853 端口 60 秒内同一 IP 建立新连接不得超过 20 个
ufw limit proto tcp from any to any port 853
# 限制 443 端口速率
ufw limit proto tcp from any to any port 443
```

## 📱 四、客户端配置：在你的终端设备上启用

### 1. Android 设备

Android 9 及以上系统原生支持全局 DoT (私有 DNS)：

1. 进入系统 **设置** -> **网络与互联网** -> **私人 DNS**。
2. 选择 **私人 DNS 提供商主机名**。
3. 填入你的自建域名：`dns.yourdomain.com`，点击保存。

### 2. iOS 设备

iOS 原生支持 DoH/DoT。您可以使用免费工具（如 `dns-profile-creator` 等在线工具）生成一个包含了你 DoH 配置的 `.mobileconfig` 描述文件，下载后在 iPhone **设置** -> **已下载的描述文件** 中安装，即可全局生效。
