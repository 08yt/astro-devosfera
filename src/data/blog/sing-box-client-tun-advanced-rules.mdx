很多刚入坑 **Sing-box** 的玩家在开启“科学上网”后，常遇到痛点：国内手机银行提示风控闪退、微信视频通话频繁卡死断联、国服游戏延迟暴涨。

这些问题的根源在于客户端没有做好 **分应用代理（Per-App Proxy）** 与 **进程黑白名单分流（Process Name Routing）**。

今天我们将手把手调优 Sing-box 的 **TUN（虚拟网卡）模式**，打造“国内直连无感、国外极速冲浪”的全天候上网体验！

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **Android (SFA)**：开启 `App Bypass`，将微信、支付宝、网银及国服手游勾选为 `Bypass Selected` 物理直连。
> - **PC 桌面端**：在 `route.rules` 顶部通过 `"process_name": ["WeChat.exe", "QQ.exe"]` 强制直连，`"process_name": ["Telegram.exe", "Discord.exe"]` 强制代理。
> - **微信通话断联**：在直连规则最上方配置私有 IP 豁免与国内公共 DNS，避免 UDP 打洞信令被假 IP (Fake-IP) 劫持。

## 🛠️ PC 桌面端 (Windows/macOS) 进程分流配置模板

在 Sing-box 客户端 `config.json` 的 `route.rules` 模块中配置：

```json
{
  "route": {
    "rules": [
      {
        "process_name": [
          "WeChat.exe",
          "WeChat",
          "QQ.exe",
          "AliPay.exe",
          "League of Legends.exe"
        ],
        "outbound": "direct"
      },
      {
        "process_name": ["Discord.exe", "Telegram.exe", "Spotify.exe"],
        "outbound": "proxy"
      },
      {
        "rule_set": ["geosite-cn", "geoip-cn"],
        "outbound": "direct"
      }
    ],
    "final": "proxy"
  }
}
```

---

## 📏 规则匹配顺序：从上到下，命中即停

`route.rules` 是**有序数组**，第一条命中的规则生效，后面的直接跳过。所以编排顺序是门学问，推荐：

1. **私有 IP / 局域网豁免**（最优先，避免内网流量进代理）
2. **进程黑白名单**（微信、网银直连；Telegram 代理）
3. **geoip/geosite 规则集**（国内直连）
4. **`final` 兜底**（一般设 proxy）

把 `geosite-cn` 放到进程规则前面，微信就会先命中"国内直连"——看起来结果一样，但进程规则更精确，建议进程优先。

## 📱 各平台进程分流的差异

| 平台 | 进程匹配 | 说明 |
|---|---|---|
| Windows/macOS | `process_name` | 支持 exe 名 / 进程名 |
| Android (SFA) | 包名 / App Bypass | 图形界面勾选，不用写 JSON |
| iOS | 受限 | 沙盒限制，用域名规则代替 |

iOS 上别纠结进程分流，老老实实用 geosite 规则集，效果接近。

## 🎮 三个典型场景的配方

**场景 1：网银 + 微信无感**
微信、支付宝、手机银行全部 `direct`，外加 `geosite-cn` 直连。注意微信视频通话走 UDP，要确认直连规则覆盖了 UDP（Sing-box 的 route 规则默认同时管 TCP/UDP）。

**场景 2：国服游戏低延迟**
国服游戏进程（`League of Legends.exe` 等）强制 `direct`，国际服用代理。别用全局 TUN 玩国服，多一跳延迟直接劝退。

**场景 3：工作分流**
公司内网域名直连，GitHub/Stack Overflow 走代理，Slack/Teams 看公司政策。

## ⚠️ FakeIP 和直连应用的经典冲突

开了 FakeIP 后，直连应用拿到的 DNS 是假 IP（如 `198.18.x.x`），如果直连规则只写了域名没写 IP 段，流量还是会被送进代理。微信语音通话断联，十有八九是这个原因。解法：直连规则里**域名和 geoip-cn 双写**，或给这类应用单独配 `dns` 直连。

## 🔍 调试：确认流量走了哪条规则

```json
{ "log": { "level": "debug" } }
```

日志会打印每条连接命中的 rule 索引。对着 `route.rules` 数组数第几条，一眼看出是顺序问题还是规则写错。

### Q1: 开启 TUN 模式后 Windows 自带应用商店 (UWP) 无法连网怎么解决？

**答**：在 Sing-box `inbounds` 的 `tun` 模块中将 `"stack"` 设为 `"system"` 或 `"mixed"`，并使用 Windows Loopback 豁免工具放行 UWP 应用。

### Q2: 为什么优质专线机场比自建节点在分流体验上更稳定？

**答**：优质商业专线机场内置成熟的全球流媒体与国内直连分流规则，搭配 **中国电信 CN2 GIA** 或 **联通 AS9929** 专线，推荐阅读 [《“饿饭CC云”深度评测》](/posts/efan-cc-cloud-review/)。

### Q3: 进程名写对了还是不生效？

**答**：先确认三点：① 大小写，Windows 上 `WeChat.exe` 和 `wechat.exe` 是两个名字；② 规则顺序，进程规则被前面的 geoip 规则抢先命中；③ 有的程序会起多个子进程（如 Chrome 每个标签页），子进程名可能不同，开 debug 日志看实际命中的进程名。

### Q4: 规则写多了会影响速度吗？

**答**：单条规则匹配是微秒级，几十条无感。但几千条域名规则建议换成二进制 `rule_set`（.srs），加载快、内存省。geosite-cn 这类大规则集不要手写，用官方编译好的。
