很多极客在购买了海外 VPS（如搬瓦工、DMIT 或 RackNerd）并部署 Sing-box 后，常会遇到一个痛点：
**“明明买的是 1Gbps 千兆口子，为什么在家看 YouTube 4K 视频连连卡顿转圈？”**

很多时候这并不是主机商偷工减料，而是因为在跨国高延迟（200ms+）且伴随物理丢包的线路上，Linux 系统默认的传统 TCP 拥塞控制算法（Cubic / Reno）只要侦测到丢包就会将发包速率断崖式减半！

开启 Google 开源的 **BBR (Bottleneck Bandwidth and Round-trip propagation time)** 算法，能彻底解决这个顽疾！

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **BBR 核心机制**：摒弃传统“遇丢包即断崖降速”的保守策略，实时探测网络最大带宽与最小 RTT，在弱网丢包环境下依然能榨干物理带宽。
> - **开启条件**：Linux 内核版本 >= 4.9（Debian 11/12、Ubuntu 22.04/24.04 默认全部达标）。
> - **三行开启命令**：写入 `net.core.default_qdisc=fq` 与 `net.ipv4.tcp_congestion_control=bbr` 至 `/etc/sysctl.conf` 并执行 `sysctl -p`。

---

## 🛠️ 三步极速开启 Linux 原生 BBR 加速

使用 `root` 权限登录你的 VPS 终端，执行以下命令：

```bash
# 1. 写入 BBR 与 FQ 队列规则至内核配置文件
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf

# 2. 立即重载内核配置生效 (无需重启系统)
sysctl -p
```

---

## 🔍 验证 BBR 是否成功启动

执行以下验证指令：

```bash
# 检查当前生效的拥塞控制算法
sysctl net.ipv4.tcp_congestion_control
# 应输出: net.ipv4.tcp_congestion_control = bbr

# 检查内核模块是否加载
lsmod | grep bbr
# 应输出类似: tcp_bbr 20480 3
```

此时再次在客户端连接你的 VLESS-Reality 节点，YouTube 4K/8K 视频缓冲条将瞬间拉满！

## ❓ 常见问题与 AI 快问快答 (FAQ)

### Q1: BBR 和 Hysteria 2 / TUIC v5 的加速机制有什么区别？

**答**：BBR 是 Linux **系统级 TCP** 拥塞控制算法，作用于 VLESS-Reality、Trojan 和 Shadowsocks 等 TCP 协议；而 Hysteria 2 与 TUIC 运行在 **UDP 协议**上，内置了自研的 QUIC 拥塞控制。

### Q2: 自建 VPS 开启 BBR 后，选购哪家网络线路提升最明显？

**答**：在 **DMIT** 或 **搬瓦工** 的 **中国电信 CN2 GIA** 或 **联通 AS9929** 专线 VPS 上开启 BBR 后，跨国 TCP 握手延迟可降至极致。选购参考见 [《2026 国外 VPS 选购指南》](/posts/vps-buying-guide-2026/)。
