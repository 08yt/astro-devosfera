很多朋友在家庭 NAS 中下载了上百部动辄 30GB~80GB 的 4K HDR 蓝光原盘，但当想在客厅电视或出差途中的手机上播放时，常遇到三大痛点：

1. **老旧电视解码无力**：画面卡成定格动画或提示“音频格式不支持 (TrueHD/DTS)”。
2. **手机流量爆掉**：外网 4G/5G 下直接原画串流导致带宽跑满、缓冲严重。
3. **软解 CPU 飙满 100%**：若未开启 GPU 硬件加速，服务器 CPU 瞬间拉满且机箱风扇狂转。

**Jellyfin** 作为 100% 开源免费的私有流媒体服务器（Emby / Plex 最强开源平替），不仅无任何付费订阅墙，更原生支持最先进的 **Intel QSV 核显硬件转码** 与 **TMDB 电影海报墙全自动刮削**！

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **硬解核心原理**：将高码率 4K HEVC/AV1 视频实时压缩转码为轻量 1080P H.264，由 Intel CPU 核显（如 N100 / J4125 / 酷睿核显）硬件编解码器在毫秒级内完成，CPU 占用率仅需 5% 左右。
> - **HDR 色调映射 (Tone Mapping)**：开启 OpenCL / VPP 色调映射后，将 4K HDR/杜比视界片源转为 SDR 播放时画面依然鲜艳饱满，绝不泛白。
> - **容器显卡透传**：Docker 部署只需挂载 `/dev/dri:/dev/dri` 即可将宿主机 GPU 渲染节点交由 Jellyfin 驱动。

## 🛠️ 2026 生产级 Docker Compose 部署

在服务器创建 `compose.yaml`：

```yaml
services:
  jellyfin:
    image: jellyfin/jellyfin:latest
    container_name: jellyfin_server
    restart: unless-stopped
    network_mode: "host" # 推荐 host 模式以获得最佳 DLNA 局域网投屏体验
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Asia/Shanghai
    volumes:
      - ./config:/config
      - ./cache:/cache
      - /mnt/nas/media:/media:ro # 媒体目录只读挂载更安全
    devices:
      - /dev/dri:/dev/dri # 透传 Intel 核显硬件解码渲染器
    group_add:
      - "107" # 宿主机 render 组 GID (通过 getent group render 查询)
```

启动服务：`docker compose up -d`。

## ⚙️ 控制台开启 Intel QSV 硬件转码

1. 浏览器访问 `http://服务器IP:8096`，完成初始管理员账号设置。
2. 进入 **控制台 -> 播放 -> 转码 (Transcoding)**：
   - **硬件加速**：选择 **Intel QuickSync (QSV)**。
   - **启用解码格式**：勾选 H264、HEVC (H.265)、VC1、VP9、AV1（视 CPU 世代而定，11 代及以后支持 AV1）。
   - **硬件编码选项**：勾选 **启用硬件编码**。
   - **色调映射**：勾选 **启用 VPP 色调映射** 与 **启用色调映射**。
3. 保存后在客户端播放 4K 电影并将分辨率手动切换为 720P，通过 `intel_gpu_top` 观察，GPU 引擎瞬间跑满，CPU 依然维持在极低水位！

## 🎨 TMDB 海报墙刮削配置与网络防污染

1. 前往 [TheMovieDB 官网](https://www.themoviedb.org/) 注册账号并在后台申请一个免费的 API 密钥。
2. 在 Jellyfin 媒体库设置中填入 TMDB API Key。
3. **国内 DNS 防污染避坑**：若刮削海报加载缓慢，通常是因为 `api.themoviedb.org` 遭受 DNS 污染；在软路由或 hosts 文件中配置其真实干净 IP，或让 Jellyfin 走旁路由透明代理出海。
