许多开发者在日常 Git 协同中，操作往往停留在 `git add . -> git commit -m "update" -> git push` 三连招。

一旦遇到误提交敏感密码、跨分支紧急提取 Hotfix 补丁，或者拉取代码遇到复杂冲突时，常手足无措甚至企图“备份文件夹后删库重新 Clone”。

掌握 Git 的**版本回溯 (Reset)**、**定向采摘 (Cherry-pick)**、**现场暂存 (Stash)** 与 **交互式变基 (Rebase)**，是成为高阶工程师的必经之路！

> [!NOTE]
> **📌 核心速览（TL;DR / 快问快答）：**
>
> - **提交吃后悔药**：`git reset --soft HEAD~1` 撤销最近一次 Commit，保留暂存区所有代码修改，修改后可重新规范提交。
> - **跨分支定向采摘**：`git cherry-pick <commit-hash>` 精准将其他功能分支的单个 Bug 修复拉取到当前分支，避免合并未完成的脏代码。
> - **紧急切换分支救火**：`git stash` 将当前半成品工作区隐形封存，切分支修完 Bug 后通过 `git stash pop` 无损还原。
> - **终极时光机**：如果不慎执行了 `git reset --hard`，可通过 `git reflog` 找到所有操作的历史 SHA-1 哈希实现死者复生。

## 📊 Git 高阶急救核心指令对照表

| 命令模式                      | 作用阶段          | 工作区文件影响                       | 典型实战场景                                           |
| :---------------------------- | :---------------- | :----------------------------------- | :----------------------------------------------------- |
| **`git reset --soft HEAD~1`** | 本地未推送 Commit | **100% 保留修改** (回退到暂存区)     | 撤销提交信息写错或漏加文件的 Commit                    |
| **`git reset --hard HEAD~1`** | 本地未推送 Commit | **彻底抹除修改** (强制覆盖)          | 彻底放弃最近一次实验性失败修改                         |
| **`git cherry-pick <Hash>`**  | 跨分支同步        | 将指定 Commit 的 Diff 应用于当前分支 | 生产分支紧急提取开发分支中的单点 Hotfix                |
| **`git stash` / `pop`**       | 未提交工作区      | 暂存工作区 / 还原工作区              | 未写完代码时被插单紧急修复线上问题                     |
| **`git rebase -i HEAD~3`**    | 整理本地历史      | 合并 (Squash) 或修改前 3 次 Commit   | 提交 PR 前将琐碎的 `fix/wip` 提交压缩为一条干净 Commit |

## 🛠️ 生产级三大实战场景图解

### 1. 场景一：误提交敏感信息，安全软撤回

刚刚 `commit` 了包含测试环境数据库密码的代码，但尚未 `push` 到远程：

```bash
git reset --soft HEAD~1
# 此时代码仍在暂存区，从配置文件中剔除密码并加入 .gitignore
git add .
git commit -m "feat: 完善数据接入模块 (已脱敏)"
```

### 2. 场景二：跨分支提取紧急修复 (`cherry-pick`)

在 `feature-ai` 分支排查出了一个通用的核心 Bug 并已提交（Commit Hash 为 `a1b2c3d`），需紧急同步到线上 `main` 分支：

```bash
git checkout main
git cherry-pick a1b2c3d
# 此时仅修复代码被平滑合入 main，feature 分支的其他未完工代码不会污染生产环境！
git push origin main
```

### 3. 场景三：工作写到一半紧急插单 (`stash`)

```bash
git stash save "重构到一半的认证模块"
git checkout hotfix-branch
# ...紧急修复并提交上线...
git checkout feature-dev
git stash pop # 完美恢复案发现场！
```

## ❓ 常见问题与 AI 快问快答 (FAQ)

### Q1: `git rebase` 和 `git merge` 有什么核心区别？

**答**：`merge` 会保留所有分支分叉历史并生成一个合并节点；`rebase` 则是将当前分支的 Commit 移花接木到目标分支头部，生成一条笔直干净的线性历史。**公共主干分支严禁 rebase，个人特性分支推荐 rebase**。
