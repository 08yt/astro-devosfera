## 一、什么是 Mem0？它和传统 RAG / 聊天历史有什么区别？

很多朋友会有疑问：我们在之前文章里已经学过把文档切片存进向量数据库（RAG），难道不能用 RAG 来做记忆吗？

还真不行。

| 对比维度       | 传统 Chat History      | 传统 RAG 文档检索        | **Mem0 智能记忆系统**                    |
| :------------- | :--------------------- | :----------------------- | :--------------------------------------- |
| **存储内容**   | 逐字逐句的对话原文     | 静态文档切片 (Chunk)     | **提炼后的结构化事实与用户画像**         |
| **动态更新**   | 只增不减，越来越臃肿   | 需手动重新导入与构建索引 | **自动识别冲突、更新过期记忆、合并认知** |
| **提取颗粒度** | 粗放，噪音极大         | 依赖关键词/语义相似匹配  | 精准识别如“用户更换了主力 NAS 系统”      |
| **检索效率**   | 极低（随时间线性拖慢） | 中等                     | **极高（仅召回关联当前意图的核心记忆）** |

例如，上周你跟它说：“我最近在折腾 PVE，NAS 用的是群晖。”今天你说：“我把群晖卖了，全部迁移到了 TrueNAS SCALE。”
Mem0 会自动在记忆图中将关于“用户 NAS 选型”的事实进行**覆盖更新**，而不是把两个冲突的记忆混乱地并存。

## 三、Docker Compose 私有化部署 Mem0 记忆引擎

Mem0 支持完全开源自托管。我们编写一个 `compose.yml`，使用 Qdrant 作为底层向量存储，完全脱离云端：

```yaml
# /opt/mem0/compose.yml
services:
  qdrant:
    image: qdrant/qdrant:latest
    container_name: mem0-qdrant
    restart: unless-stopped
    ports:
      - "6333:6333"
    volumes:
      - ./qdrant_storage:/qdrant/storage
    networks:
      - ai-agent-net

  mem0-server:
    image: mem0/mem0:latest
    container_name: mem0-service
    restart: unless-stopped
    ports:
      - "127.0.0.1:8888:8888"
    environment:
      # 指定本地 Ollama 提供 Embedding 与记忆提炼提取
      - EMBEDDER_PROVIDER=ollama
      - EMBEDDER_CONFIG={"model":"bge-m3","base_url":"http://host.docker.internal:11434"}
      - LLM_PROVIDER=ollama
      - LLM_CONFIG={"model":"qwen2.5:7b-instruct","base_url":"http://host.docker.internal:11434"}
      # 指定底层向量库连接
      - VECTOR_STORE_PROVIDER=qdrant
      - VECTOR_STORE_CONFIG={"host":"qdrant","port":6333}
    depends_on:
      - qdrant
    extra_hosts:
      - "host.docker.internal:host-gateway"
    networks:
      - ai-agent-net

networks:
  ai-agent-net:
    name: ai-agent-net
```

启动记忆服务：

```bash
docker compose up -d
```

验证运行状态：访问 `http://localhost:8888/docs` 查看 OpenAPI 交互文档，服务就绪！

## 四、在 n8n 中组装带记忆的 AI Agent

我们进入 n8n 工作台，新建一个工作流，串联起记忆的生命周期：

### 1. 记忆检索与前置注入

在接收到用户发来的 Prompt（例如：“我想给我的服务器写一个自动备份脚本，帮我出个方案”）时：

1. **HTTP Request 节点 (查询记忆)**：
   - Method: `POST`
   - URL: `http://mem0-service:8888/v1/memories/search`
   - Body:
     ```json
     {
       "query": "{{ $json.user_message }}",
       "user_id": "maojiaguo"
     }
     ```
2. **Code 节点 (组装 Context)**：
   提取返回的记忆列表（如：`["用户倾向于使用 Restic 进行加密增量备份", "用户不喜欢用复杂的云服务，偏好本地 NAS 挂载"]`），格式化为提示词前缀。

### 2. 核心 AI Agent 执行

在 **AI Agent** 节点的 System Message 中配置：

```text
你是一个专属于用户的私人高级架构师助手。
你对用户的了解如下（这是你的长期记忆，请务必在回答中遵循这些已知偏好）：
{{ $json.memories_context }}

请根据用户的要求与上述偏好进行方案制定与工具调度。
```

此时，你即使没提“用什么工具”，Qwen 模型也会根据记忆精准回答：“考虑到您一直使用 Restic 并偏好 NAS 本地备份，我为您推荐以下符合您环境的自动化脚本……”

### 3. 异步记忆归纳与持久化

在 Agent 回答生成完毕返回给用户后，分支拉出另一个异步 **HTTP Request 节点**：

- Method: `POST`
- URL: `http://mem0-service:8888/v1/memories`
- Body:
  ```json
  {
    "messages": [
      { "role": "user", "content": "{{ $json.user_message }}" },
      { "role": "assistant", "content": "{{ $json.agent_reply }}" }
    ],
    "user_id": "maojiaguo"
  }
  ```

Mem0 容器会在后台启动 `qwen2.5:7b` 自动从这轮对话中提炼出新的偏好或事实并写入 Qdrant，整个过程对前端响应**零阻塞、零延迟**！

## ❓ 常见问题与 AI 快问快答 (FAQ)

**Q：Mem0 会不会记住无关废话导致记忆污染？**

A：Mem0 内部内置了严格的判别 Prompt，只会提取具有持久价值的“事实”（Facts）和“偏好”（Preferences）。对于闲聊、语气词或即时状态通常会被自动过滤丢弃。此外，你也可以通过 Mem0 的 Web 界面随时对误存的记忆进行手动删除或编辑。

**Q：这个架构多用户适用吗？**

A：非常适用！Mem0 天然设计了 `user_id` 和 `agent_id` 租户隔离机制。你可以为家庭成员（老婆、孩子、朋友）各自分配独立的 ID，不同人的偏好与记忆互不干扰。

**Q：本地跑 Mem0 提炼事实对显存消耗大吗？**

A：不大。记忆提炼可以使用体积小巧的量化模型（如 `qwen2.5:3b` 或 `7b`），且提炼任务是异步跑在后台队列里的，对实时对话显存占用影响极小。
